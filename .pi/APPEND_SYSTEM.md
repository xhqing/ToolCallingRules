# ToolCallingRules · 项目硬约束

身份与角色见本仓库根 `AGENTS.md`；团队通用规则见全局 `~/.pi/agent/AGENTS.md`，此处不重述。

## 本项目是什么

一套注入 system prompt 的 **LLM 工具调用规则集**：22 条规则 / 7 大类。中文正文 `toolCallingRules.md`，英文正文 `toolCallingRules_en.md`，两版逐条对应。仓库里没有代码，正文就是产品。

## 硬约束

- **编号即契约**：规则编号 1–22 连续、不复用、不跳号。新增只能追加到末尾（23、24…）；删除某条必须把后续编号一起重排。中途插号会让下游 prompt 里的「规则 12」指向截然不同的内容。
- **七类目顺序固定**：调用前准备 / 参数格式 / 路径与标识符 / 关联参数 / 工具选择与调用策略 / 错误恢复 / 安全与副作用。新规则优先挂进已有类目，确需新类目才在末尾追加第八类。
- **每条规则的写法固定**：`编号. **一句话结论（加粗）。** 紧接着简短解释或可执行判据。`。规则是给模型照着做的，不是给人讲解的——一条只讲一件事，判据要能落到具体动作。
- **关键示例不许删**：第 4 条的 JSON 正误对照代码块、第 9 条的路径正误对照表，是这两条规则可执行性的全部来源，可以改写、不能删掉（删了规则就退化成口号）。
- **中英同步**：改 `toolCallingRules.md` 必须同轮改 `toolCallingRules_en.md`，编号、类目、条数、示例一一对齐；英文按地道美式英语写，术语两版保持一致。
- **README 两版跟着改**：`README.md` / `README_cn.md` 的徽章 `Rules-22`、类目区间表（1–3 / 4–8 / 9–11 / 12–13 / 14–16 / 17–19 / 20–22）、正文「22 条规则，分为 7 个类别」必须与实际一致。
- **定位边界**：这里只放工具调用行为规则。商业计划、平台运营打法、店铺资质这类与本规则集无关的笔记不入库（已在 `.gitignore` 里忽略，保持原样即可）。
- **许可证**：PolyForm Noncommercial 1.0.0（非商业），与 AgentCortex 的 MIT 不同——不得整段搬运与本许可证冲突的第三方文本进来。

## 验证

```bash
echo "cn: $(grep -c '^[0-9]\+\. \*\*' toolCallingRules.md)  en: $(grep -c '^[0-9]\+\. \*\*' toolCallingRules_en.md)"
diff <(grep -o '^[0-9]\+\. \*\*' toolCallingRules.md) <(grep -o '^[0-9]\+\. \*\*' toolCallingRules_en.md) && echo 编号对齐
grep -c '^## ' toolCallingRules.md
```

- 条数两边都应是 22、编号序列 diff 为空、`##` 数是 7；动了条数就同步改 README 徽章与这里。
- 规则内容改动后逐条对照中英文，确认译文没漏掉判定条件——漏一个条件比漏一整句更严重。
